# موتور قوانین صف، اعلان‌های بله و دسترسی سرپرست — نسخه بتا ۸

## دامنه

موتور `qpanel/queue_policies.py` یک فایل `local_queue_policies.json` (فقط قوانین بدون توکن و رمز) می‌سازد؛ این فایل به صورت پیش‌فرض در `.gitignore` قرار دارد. قوانین هر صف دارای چهار گروه هستند:

- `alerts`: آستانه تعداد منتظر، طولانی‌ترین زمان انتظار، حداقل اعضای آماده، بازه سکوت هشدار و فعال‌سازی اختیاری بله.
- `staffing`: تعداد برنامه‌ریزی‌شده نیروی صف، سقف خروج همزمان به درصد، سقف خروج به تعداد، حداقل افراد on-duty.
- `pause_reasons`: شناسه امن انگلیسی به همراه برچسب فارسی. از جمله break، lunch، training، meeting، after_call، survey، technical.
- `supervisors`: کاربران موجود و صف‌های مجاز + مجوزهای `view`، `pause`، `membership`، `monitor`، `hangup`، `priority`.

برای نمایش وضعیت، رویداد `QueueMember` Asterisk دارای `PausedReason` است. در نسخه فعلی، `QueuePause` از شناسه دلیل انتخابی استفاده می‌کند، نه یک API جدا برای ساخت Device State جدید. دلیل `survey` به معنی **ارسال واقعی تماس به نظرسنجی نیست**.

## سقف خروج ۵۰٪

برای صف ۱۰ نفره، ۵۰٪ و سقف عددی ۵ به معنی حداقل ۵ نفر *on-duty* (اعضای فعال شامل آماده یا مشغول) است. برای جلوگیری از دورزدن با QueueRemove، مبنا `roster_size` ثابتِ پیکربندی‌شده است. اگر تعریف نشده باشد، خروج خودکار از مسیر کنترل‌شده رد می‌شود. تا ۶۰ ثانیه، خروج‌های در حال اجرا روی همین فرآیند رزرو می‌شوند تا فرمان دوم نتواند snapshot قدیمی را دور بزند.

> توجه: اگر اپراتورهای دیگر از Issabel یا API دیگری صف را تغییر بدهند یا چند سرور هم‌زمان SaneQueue داشته باشیم، سیاست درون‌فرآیندی ضمانت اتمیک جهانی ندارد. نسخه production به سرویس هماهنگ‌کننده مشترک و کنترل مستقل نیاز دارد.

## اعلان بله

نسخه آزمایشی از قالب Bot API بله `sendMessage` و فقط مقصد ثابت `https://tapi.bale.ai` استفاده می‌کند. تماس‌گیرنده و شماره تماس در پیام قرار نمی‌گیرند. ارسال از سمت سرور با توکن **خارج از سورس و فایل JSON** انجام می‌شود.

برای آزمایش روی ویندوز، می‌توانید فایل `RUN_WITH_BALE_ALERTS_18886.ps1` را از PowerShell اجرا کنید. این فایل توکن را با ورودی مخفی دریافت می‌کند، Chat ID می‌خواهد و همان CMD برنامه را با متغیرهای محیطی راه می‌اندازد.

لازم است (۱) ربات و Chat ID معتبر باشد، (۲) checkbox «ارسال اعلان بله» برای آن صف فعال باشد، و (۳) سرور توان HTTPS خروجی به بله را داشته باشد. اعلان در نخستین عبور از آستانه فرستاده می‌شود و تا رفع هشدار و رخداد بعدی تکرار نمی‌شود؛ Cooldown حداقل ۶۰ ثانیه است.

بدون فایل PowerShell مخصوص و با اجرای معمولی CMD، بله کاملاً غیرفعال است. سرویس background داخل یک فرآیند local Flask هر ۳۰ ثانیه فقط اگر محیط فعال و AMI متصل باشد وضعیت صف‌ها را بررسی می‌کند؛ **تحویل پایدار پس از خاموش‌شدن ویندوز، قطع اینترنت، یا Crash تضمین ندارد**. برای نسخه عملیاتی نیازمند صف پیام و ثبت تحویل است.

## ساخت دسترسی سرپرست

سیاست `supervisors` صف‌های قابل مشاهده و انواع عمل مجاز را تعیین می‌کند و در APIهای داده/کنترل نیز بررسی می‌شود، **اما نسخه local preview بدون احراز هویت واقعی، همه درخواست‌ها را کاربر demo/admin می‌گیرد**. بنابراین از آن برای مدیریت واقعی کاربرهای سازمان یا روی سرور عمومی استفاده نکنید؛ این مرحله زیرساخت سیاست است، نه RBAC تولیدی کامل.

## آزمون‌های لازم روی ایزابل

1. تغییر آستانه و عبور از آن با شش تماس آزمایشی؛ تأیید تنها یک هشدار.
2. قرار دادن یک تماس در انتظار ۳۰۱ ثانیه و کنترل هشدار زمان (با تماس آزمایشی و بدون دخالت در صف مشتری).
3. Pause با علت `survey` و تأیید فیلد `PausedReason` در QueueStatus.
4. تنظیم `roster_size=10`, `50%`, `5`, `min=5` و پنج Pause آزمایشی؛ نفر ششم باید 409 برگرداند.
5. برای بله، یک بات و چت خصوصی تست؛ فعال‌سازی فقط برای همان صف، مشاهده نتیجه ارسال و خاموش‌کردن بلافاصله بعد از تست.
6. احراز هویت و role واقعی جدا از demo-login، پیش از نسخه تولیدی.
