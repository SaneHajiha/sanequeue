# SaneQueue beta.27 — نصب و پذیرش پایلوت

این نسخه برای نصب آزمایشی کنترل‌شده است؛ تأیید تمام نسخه‌های مرکز تلفن یا بار ۵۰–۱۰۰ تماس هم‌زمان نیست. کد جاری روی شاخهٔ `feature/reporting-phase2` است، نه تماماً روی master.

## نصب از GitHub

برای تکرارپذیری، مقدار `REF` را با SHA کامل نسخهٔ بررسی‌شده جایگزین کنید. استفاده از نام شاخه آخرین تغییرات همان شاخه را دریافت می‌کند.

```bash
REF=feature/reporting-phase2
curl -fL --proto '=https' --tlsv1.2 \
  "https://raw.githubusercontent.com/SaneHajiha/sanequeue/$REF/scripts/install.sh" \
  -o /tmp/sanequeue-install.sh
sudo env SANEQUEUE_REF="$REF" bash /tmp/sanequeue-install.sh
sudo sanequeuectl status
```

روی میزبان Linux/systemd دارای Asterisk محلی اجرا کنید. نصب نخست نام مدیر، رمز انتخابی ۱۲–۲۰۰ نویسه، داخلی سرپرست و آدرس پنل را می‌پرسد؛ رمز پیش‌فرض مشترک وجود ندارد. در ارتقا حساب‌ها حفظ می‌شوند. Python ایزابل جایگزین نمی‌شود؛ ابزارهای طراحی، Node، Playwright و مدل‌های AI روی PBX نصب نمی‌شوند. این اسکریپت Asterisk/MariaDB را restart نمی‌کند، ولی سرویس‌های خود SaneQueue برای ارتقا بازآغاز می‌شوند.

صف‌ها و داخلی‌ها از موجودی PBX کشف می‌شوند. گزارش صف از queue_log خوانده می‌شود. برای CDR/CEL، تنظیمات **حساب محدود SELECT-only** باید در `/etc/sanequeue/reporting-sql.ini` موجود باشد؛ نصب‌کننده رمز مدیر دیتابیس PBX را به وب‌اپ کپی نمی‌کند و CEL غیرفعال را بدون بررسی فعال نمی‌کند. نبود این منبع به معنی نبود تماس یا مشکل نیست. راهنمای منبع و شاخص‌ها: [فاز گزارش](REPORTING_PHASE2.md).

## کنترل جداگانه

راهنمای کامل: [کنترل سرویس‌ها](SERVICE_MODULE_CONTROL.md).

| نام | کاربرد |
|---|---|
| monitoring | جمع‌آوری زنده و کشف موجودی |
| reporting | ورود و پردازش آرشیو گزارش |
| exports | ساخت فایل‌های خروجی |
| plans | زمان‌بندی گزارش‌ها |
| ai | تبدیل صوت به متن؛ نیازمند پیکربندی و انتخاب صریح |
| generative | تحلیل متن؛ نیازمند پیکربندی و انتخاب صریح |
| surveys | آداپتور نظرسنجی تلفنی؛ نیازمند binding و مسیر تأییدشده |
| media | پردازش صوت رخدادها |

```bash
sudo sanequeuectl disable --module plans --dry-run
sudo sanequeuectl disable --module plans
sudo sanequeuectl enable --module plans
sudo sanequeuectl disable --module reporting --cascade
sudo sanequeuectl enable --module reporting
sudo sanequeuectl enable --module exports
sudo sanequeuectl enable --module plans
```

غیرفعال‌کردن والد بدون تعیین تکلیف وابسته‌ها رد می‌شود؛ `--cascade` آن‌ها را صریحاً غیرفعال می‌کند. فعال‌کردن والد، فرزندان را خودکار فعال نمی‌کند. وضعیت غیرفعال پس از ارتقا و شروع مجدد سرویس حفظ می‌شود. این کنترل‌ها مجوز منوی کاربران را تغییر نمی‌دهند. کال‌بک، انتظار داخلی و Caller ID از تنظیمات قابلیت‌های تلفنی پنل کنترل می‌شوند؛ FastAGI مشترک را برای خاموش‌کردن یکی از آن‌ها متوقف نکنید. قابلیت برنامه‌ریزی‌شدهٔ پیاده‌نشده با روشن‌کردن سرویس ساخته نمی‌شود.

## شواهد این نسخه

- آزمون Python محلی: ۱۰۱۰ موفق، ۲۰ ردشده به‌دلیل پیش‌نیاز/سیستم‌عامل، ۳۳۴ زیرآزمون؛ بررسی‌های تکمیلی نصب و کنترل جدا ثبت شده‌اند.
- مرورگر مستقل: ۳۰ آزمون موفق، فارسی/انگلیسی، روشن/تیره، موبایل/دسکتاپ، تقویم، دسترس‌پذیری خودکار و PNG/SVG. این تعداد جای بررسی همهٔ صفحات محصول نیست.
- نصب واقعی روی آزمایشگاه Asterisk 20.12؛ ورود موجود و تقویم/نمودار واقعی روی پورت ۵۰۰۰ بررسی شدند. ۱۸۸۹۷ پیش‌نمایش خواندنی همان نسخه و همان آرشیو است؛ مجموعهٔ تکراری importer راه‌اندازی نشده است.
- ارتقای کپی آرشیو: ۱۷۶۰۳ رویداد قبل و بعد، projection نسخه ۱۰ تا انتهای آرشیو، ۱۰٫۷ ثانیه دیواری، ۲٫۷ ثانیه CPU و حدود ۲۳ MiB RSS.
- گزارش واقعی: ۴۹۱ مراجعه، ۴۳ پاسخ، ۴۴۸ رهاشده. CSV/XLSX/PDF از دکمهٔ خود پنل ساخته و دانلود شدند؛ CSV شامل ۴۹۱ ردیف داده، Excel دارای ۴۹۱ ردیف داده به‌علاوهٔ عنوان‌ها بود. آزمون قالب PDF، تأیید بصری تمام صفحات PDF نیست.
- خاموش/روشن‌کردن plans روی systemd واقعی و جلوگیری از restart در حالت غیرفعال تأیید شد؛ reboot کل سرور انجام نشد.
- آزمون ماهانهٔ **دادهٔ مصنوعی**: ۳۰هزار شناسه، ۳۳۳۳۰ مراجعه، ۱۹۳۵۰۰ رویداد. موتور خصوصی ماهانه روی سقف ۲۵٪ یک هسته، ۵۳٫۴ ثانیه دیواری، ۱۳٫۳ ثانیه CPU و حدود ۳۲ MiB RSS؛ رتبه‌بندی و اجتماع حضور با انتظارهای مستقل تطبیق داشت. این آزمون تماس واقعی یا کیفیت RTP نبود.

دو ایراد ارتقا در آزمایش واقعی اصلاح شدند: تبدیل مسیر قدیمی داده به مسیر واقعی برای storeهای خصوصی و حفظ مجوز owner-only پوشهٔ خروجی. بازگردانی خودکار نسخه/تنظیمات/سرویس‌ها در شکست اولیه و شکست پذیرش وب مشاهده شد. PID پردازش Asterisk در کل آزمایش ۱۳۳۰۴۱ باقی ماند؛ این شواهد، تضمین عمومی عدم اختلال در هر PBX نیست.

## پیش از نصب زیر بار شرکت

پشتیبان خصوصی خارج از سرور، پنجرهٔ تغییر و مسیر بازگشت داشته باشید؛ نخست بخش‌های اختیاری سنگین خاموش باشند. از [چک‌لیست پایلوت](PILOT_INSTALL_CHECKLIST.fa.md) استفاده کنید. تماس واقعی پاسخ/رهاشدن/انتقال/پارک، ضبط و مجوز، قطعی منبع، CPU/RAM/IO/WAL و کیفیت صدا را قبل/حین/بعد مقایسه کنید. در این آزمایشگاه ترانک خارجی وجود ندارد؛ مسیر بیرونی و سازگاری Issabel 4/5 و Asterisk 16/18 مستقل آزموده نشده‌اند.

## وضعیت توسعهٔ گزارش

کد و نصب این پایلوت به معنی بسته‌شدن همهٔ توسعه نیست. موتور ماهانه فعلاً CLI خصوصی روی پشتیبان ثابت است؛ اتصال job/API با مجوز جاری، گزارش‌ساز مستقل CDR/PDF سفارشی، Ring Group/Follow-Me پیش از صف و چند جریان پیشرفتهٔ پیگیری/نظرسنجی/آرشیو هنوز در [فهرست تکمیل](REPORTING_COMPLETION_CHECKLIST.fa.md) بازند. آن‌ها را با «فقط تست باقی است» معرفی نکنید.
