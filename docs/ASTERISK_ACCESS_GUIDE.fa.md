# اتصال امن برای تست SaneQueue با Asterisk / Issabel

**از ارسال رمز AMI، فایل خام `manager.conf`، کلید SSH و توکن در ChatGPT یا GitHub خودداری کنید.** حساب مخصوص تست، موقت و دارای حداقل دسترسی داشته باشید.

## فاز ۱ — تشخیص بدون تغییر در PBX

روی سرور خودتان با SSH اجرا کنید:

```bash
asterisk -rx 'core show version'
asterisk -rx 'module show like app_queue'
asterisk -rx 'queue show'
asterisk -rx 'core show channels count'
```

متن ارسالی باید از شماره مشتریان، نام افراد و اطلاعات داخلی حساس پاک‌سازی شود. اگر صف آزمایشی `8001` دیده می‌شود، نتیجهٔ آن را جداگانه بررسی کنید.

## فاز ۲ — حساب AMI فقط خواندنی

- AMI فقط در LAN یا روی SSH tunnel و loopback در دسترس باشد؛ **TCP/5038 را روی اینترنت باز نکنید.**
- حساب مجزا برای نرم‌افزار و فقط برای خواندن صف، اعضا، channel events و CoreShowChannels (در حد نیاز و سازگاری نسخه) بسازید.
- مجوز `write=none`؛ هیچ Originate، Hangup، QueuePause، QueueAdd/Remove یا ChanSpy در فاز اول.
- دسترسی از IP آزمایش محدود و رویدادهای لاگ کنترل شود؛ رمزها محلی و خارج از Git نگهداری شوند.
- مطمئن شوید دسترسی به صف‌ها در سطح برنامه نیز محدود شده و کاربران دیگر داده را نمی‌بینند.

## فاز ۳ — کنترل‌های پرخطر، فقط تماس آزمایشی

Pause/Resume، تغییر اولویت، قطع تماس، شنود، نجوا و Barge به مجوزهای متفاوت و تست قابل بازگشت احتیاج دارند. این‌ها را روی PBX آزمایشی با صف و داخلی آزمایشی، با رعایت قوانین و سیاست شنود مکالمات بررسی کنید. دسترسی محدود، گزارش عملیات و تأیید سرپرست ضروری است.

## دسترسی این گفتگو

من می‌توانم صفحات **بازشده در مرورگر Chrome متصل** را در حالت خواندنی بررسی کنم؛ در این چت دسترسی مستقیم SSH/AMI به LAN و دستگاه‌ها ندارم. برای اجرای تست Asterisk، اسکریپت‌های read-only را در محیط خود اجرا و خروجی بدون اطلاعات حساس را بارگذاری کنید، یا در محیط Work با مجوز صریح از اتصال کنترل‌شده استفاده کنید. رمز یا پورت عمومی برای من ایجاد نکنید.
