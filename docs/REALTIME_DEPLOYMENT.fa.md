# راه‌اندازی Redis و WebSocket · beta.21

[English](REALTIME_DEPLOYMENT.md)

حالت جدید به‌صورت صریح فعال می‌شود؛ اجرای نصب‌کنندهٔ پایه به‌تنهایی حالت قدیمی را مهاجرت نمی‌دهد. برای هر PBX یک Collector منتخب و یک پردازش gateway اجرا کنید. دریافت داده در وب و WebSocket از Redis است و هنگام خرابی Redis به AMI برنمی‌گردد.

## پیش‌نیاز و پیکربندی

از Python مستقل ۳٫۱۰ تا ۳٫۱۲ استفاده کنید و `requirements/modern.txt` را در venv همان نسخه نصب کنید. Redis خصوصی، دارای رمز و محدودیت حافظه تهیه کنید؛ در نصب آزمایشی سقف ۱۲۸ مگابایت تعیین شد. Redis و AMI بدون رمزنگاری نباید روی اینترنت قابل دسترس باشند.

نمونهٔ `samples/collector.ini.example` را در `/etc/sanequeue/collector.ini` قرار دهید و هویت خواندن AMI و آدرس خصوصی Redis را وارد کنید. هویت آزمایشی Collector با `read=system,call,agent,reporting` و `write=reporting` و دسترسی فقط از loopback ساخته شد. ممنوع‌بودن Hangup، Originate، QueuePause، Command، BlindTransfer و Park برای آن بررسی شد. این سطح دسترسی عمداً بعضی فهرست‌های PJSIP و پارک را نمی‌خواند؛ مجوز Action با کلاس رویداد متفاوت است. برای سبزشدن یک کارت اختیاری، مجوز نوشتن `system` یا `call` را خودکار اضافه نکنید.

در `/etc/sanequeue/control.ini` بخش `[ami]` با `host`، `port`، `user` و `password` هویت جداگانهٔ کنترل سرپرست تعریف کنید. فقط فرمان‌ها و فیلدهای allowlist برنامه قابل ارسال‌اند. مسیر کنترل فعلاً به AMI محلی یا تونل خصوصی نیاز دارد؛ TLS مستقل برای این مسیر پیاده نشده است. مسیر Collector گزینهٔ TLS با اعتبارسنجی گواهی دارد.

فایل‌های خصوصی INI باید مالک `root:sanequeue` و مجوز `0640` داشته باشند. رمزها را وارد GitHub، آرگومان فرمان یا عکس مستندات نکنید. رمز پیش‌فرض عمومی برای مدیر وجود ندارد؛ نصب‌کننده رمز می‌پرسد و [راهنمای بازیابی](ADMIN_ACCESS.fa.md) روش تغییر را توضیح می‌دهد.

## فعال‌سازی

1. پس از توقف نوشتن برنامه، از سرویس فعلی، `/etc/sanequeue` و `/var/lib/sanequeue` با حفظ مالکیت و مجوزها پشتیبان بگیرید. سورس و venv نسخهٔ قبلی را نگه دارید.
2. قالب `deploy/sanequeue-collector.service` را به‌عنوان سرویس Collector نصب کنید.
3. نمونهٔ `deploy/gateway.env.example` را در `/etc/sanequeue/gateway.env` قرار دهید. Origin دقیق HTTPS، داخلی‌های مجاز، context انتقال و نام parking lot واقعی این PBX را تنظیم کنید. اعداد نمونه به معنی شناسایی خودکار داخلی‌ها نیستند. عملیات پیشرفته تنها با فهرست صریح فعال می‌شوند.
4. قالب `deploy/sanequeue-asgi.service` را به‌جای سرویس داشبورد و با نام `sanequeue.service` نصب کنید. اتصال را پشت reverse proxy روی loopback نگه دارید؛ نمونهٔ nginx هدرهای WebSocket را دارد. برای HTTPS واقعی، گواهی سازمان و `SANEQUEUE_HTTPS=1` لازم است.
5. `systemctl daemon-reload`، سپس `systemctl enable --now sanequeue-collector` و `systemctl restart sanequeue` را اجرا کنید. Asterisk یا dialplan را restart/rewrite نکنید.
6. فرمان `/opt/sanequeue/.venv/bin/python -m sanequeue.realtime --config /etc/sanequeue/collector.ini --status` سلامت را فقط از Redis می‌خواند. API مدیر `/api/runtime/metrics` است و پس از ورود، نشان WebSocket باید دیده شود.

پورت‌های ۱۶۳۷۹ برای Redis و ۱۸۸۹۶ برای gateway فقط انتخاب محیط آزمایشی بودند؛ وابستگی نصب مشتری نیستند.

## رفتار و محدودیت‌ها

Origin، نشست واقعی Flask، نقش، scope صف و لغو نشست در هر به‌روزرسانی WebSocket بررسی می‌شوند. هر دو ثانیه snapshot کاملِ فیلترشده ارسال می‌شود. سقف فعلی ۱۰۰ اتصال، ۵۱۲ کیلوبایت در هر snapshot، ده projection هم‌زمان و سه ثانیه مهلت ارسال است. پیام عملیاتی از WebSocket پذیرفته نمی‌شود. فرمان HTTP به CSRF، مجوز، state تازه، کانال دقیق و گیت موقت همان صف نیاز دارد.

SQLite WAL وضعیت فرمان، رزرو ظرفیت، لغو نشست و outbox هشدار را روی یک نود نگه می‌دارد. این نسخه HA چندنودی نیست. یک پردازش gateway اجرا کنید؛ گیت کنترل و workerهای آن محلی‌اند. رزرو ظرفیت در SQLite بین پردازش‌ها سری می‌شود، ولی این به معنی پشتیبانی کامل چندنودی نیست.

خواندن عادی داشبورد، کانال، مسیر تماس و سلامت از Redis است. ابزار عیب‌یابی صریح مدیر همچنان می‌تواند اتصال کوتاه AMI باز کند؛ این کار جزو refresh خودکار نیست. فهرست اختیاری تجهیزات هر ۱۲۰ ثانیه روی همان اتصال Collector خوانده می‌شود و نبود مجوز/درایور را به‌صورت فهرست ناقص نشان می‌دهد. هویت خواندن عمداً به هویت کنترل ارتقا نمی‌یابد.

ارسال بله به فعال‌سازی صریح محیط، token/chat و سیاست هر صف نیاز دارد. outbox دارای lease، retry، سقف و cooldown پایدار است؛ تحویل حداقل یک‌باره است و احتمال پیام تکراری در قطع شبکه وجود دارد. در نصب آزمایشی token ارائه نشد و ارسال واقعی بله ادعا نمی‌شود.

## پذیرش و بازگشت

روی هر PBX، مجوز صف، لغو نشست، قطع Collector، توقف/ادامه، انتقال، پارک و صدا را دوباره آزمایش کنید. `202` فقط پذیرش است. وضعیت فرمان‌ها `pending/confirmed/rejected/unknown` است و برخی فرمان‌های انتقال/Originate ممکن است تا تأیید رویدادی یا تلفنی نامعلوم بمانند. فرمان نامعلوم را خودکار تکرار نکنید.

برای rollback، gateway و Collector را متوقف کنید؛ سرویس، symlink سورس و محیط نسخهٔ قبلی را از پشتیبان برگردانید؛ daemon-reload و restart داشبورد انجام دهید. قطع Redis به‌تنهایی rollback نیست و حالت جدید را عمداً نامعتبر می‌کند. بازگشت این برنامه نیاز به restart استریسک ندارد.

نتایج و محدودیت‌های واقعی در [ممیزی beta.21](AUDIT_BETA21.md) آمده است. آزمون مرورگر روی دو صف، ظرفیت هزاران مکالمه را ثابت نمی‌کند.
