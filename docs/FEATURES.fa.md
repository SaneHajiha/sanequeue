# امکانات مانیتورینگ SaneQueue

این نسخه فاز اول توسعه است: **مانیتورینگ و کنترل صف**. گزارش‌گیری تاریخی به درخواست مالک پروژه در فاز دوم قرار دارد؛ کد آزمایشی آن به‌صورت پیش‌فرض غیرفعال است.

| قابلیت | وضعیت و رفتار |
| --- | --- |
| داشبورد فارسی و انگلیسی | راست‌چین واقعی، فونت محلی وزیرمتن، بدون نیاز به CDN |
| صف‌ها و کارشناسان زنده | دریافت دوره‌ای از AMI؛ فاصله پیش‌فرض ۵ ثانیه |
| وضعیت کارشناس | آماده، مشغول، در مکالمه، در حال زنگ، نگه‌داشته‌شده، استراحت و خارج از دسترس |
| اطلاعات تماس منتظر | نام، شماره، موقعیت، زمان انتظار، اولویت و صف |
| شمارنده‌ها | تماس منتظر، پاسخ‌داده، رهاشده و تعداد عضویت‌های آماده؛ از آخرین reset صف |
| دسترسی به صف مشخص | بخش `user_queues` با نام نمایشی صف؛ محدودیت در سرور اعمال می‌شود |
| نقش‌ها | بیننده، کارشناس، سرپرست و مدیر؛ نقش پیش‌فرض بیننده |
| وضعیت خود کارشناس | نقش agent فقط رابط‌های خودش در `agent_interfaces` را متوقف/فعال می‌کند |
| تغییر وضعیت توسط سرپرست | توقف/ادامه با دلیل، کنترل CSRF و ثبت نتیجه |
| حداقل آمادگی تیم | تعداد و درصد؛ از توقف/حذف توسط این پنل جلوگیری می‌کند؛ بر تغییرات مستقیم PBX یا پنل‌های دیگر حاکم نیست |
| اولویت تماس | مقدار دلخواه یا انتقال به ابتدای صف با QueueChangePriorityCaller و Immediate=yes |
| شنود، نجوا و ورود به مکالمه | ChanSpy روی تلفن داخلی مجاز سرپرست؛ تماس به تلفن سرپرست برقرار می‌شود |
| عضویت کارشناسان | افزودن عضویت پویا توسط مدیر، حذف و تغییر penalty؛ عضویت ثابت از ایزابل مدیریت می‌شود |
| قطع تماس منتظر | فقط کانال موجود در صف مجاز و پس از تأیید داخل رابط |
| زمان استراحت | از LastPause در Asterisk |
| جزئیات تماس فعال | طول عمر کانال و شماره متصل در صورت مجوز CoreShowChannels؛ معادل زمان خالص مکالمه نیست |
| هشدارها | انتظار طولانی، تعداد تماس منتظر، صف بدون کارشناس آماده، استراحت طولانی |
| هشدار صوتی | اختیاری با فعال‌سازی کاربر؛ حداکثر یک هشدار در دقیقه در همان مرورگر |
| جست‌وجو و فیلتر | صف، کارشناس، وضعیت و ترکیب فیلترها |
| نمای دیواری | حذف ناوبری، اعداد بزرگ؛ خروج با Escape |
| پوسته تیره | ترجیح مرورگر ذخیره می‌شود |
| تاریخ شمسی | ساعت و تاریخ نمایشی فارسی؛ داده‌های PBX دستکاری نمی‌شوند |
| وضعیت اتصال | خطای ارتباط و داده کهنه متمایز از صفر واقعی |
| ردپای عملیات | کاربر، زمان، صف، کارشناس، عملیات و کد نتیجه؛ فایل چرخشی ۵ مگابایتی + یک نسخه قبلی |
| نصب | نصب‌کننده systemd، Dockerfile، Compose و راهنمای اتصال AMI |

## مرزهای نسخه فعلی

- «ورود به مکالمه» همان ChanSpy Barge است؛ جایگزین سامانه کنفرانس مستقل ConfBridge نیست.
- پاسخ موفق Originate یعنی درخواست پذیرفته شده؛ شنود موفق به پاسخ تلفن سرپرست و تماس فعال بستگی دارد.
- آمادگی تیم یعنی عضو دارای وضعیت معتبر و غیرمتوقف (شامل عضو در مکالمه). «آزاد برای پاسخ» شاخص جداگانه داشبورد است.
- تغییر وضعیت واقعی دستگاه، ثبت SIP و مشغول بودن خط از Asterisk دریافت می‌شود؛ پنل آن‌ها را جعل نمی‌کند.
- ورود/خروج و penalty عضویت پویا ممکن است با reload یا تنظیمات ایزابل بازنویسی شود.
- پنل رویدادهای بین دو نمونه‌برداری را به‌عنوان تاریخچه کامل تماس ذخیره نمی‌کند.
- کنترل‌ها با تست‌های شبیه‌سازی AMI بررسی می‌شوند؛ آزمون نهایی شنود/نجوا/جابجایی با تماس آزمایشی در محیط هر پروژه لازم است.
- گزارش تاریخی، SLA دوره‌ای، خروجی Excel، ضبط و پخش مکالمه و اتصال CRM در این فاز به‌عنوان قابلیت تکمیل‌شده اعلام نمی‌شوند.
