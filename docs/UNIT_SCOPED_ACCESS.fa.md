# دسترسی واحدها و اتصال سایت: وضعیت و طراحی

## وضعیت فعلی

مجوز `view` به‌همراه فهرست صف‌ها برای نقش‌های مجاز اعمال می‌شود. `caller_details`، `report_export`، `recording_play` و `recording_download` مجوزهای جداگانه‌اند. مجوز صوت هنگام دریافت فایل دوباره بررسی می‌شود و اگر مالکیت همهٔ بخش‌های ضبط یا صف‌های مرتبط ثابت نباشد، صوت رد می‌شود. مجوز یک صف، دسترسی به تمام داخلی‌ها یا تمام CDR مرکز تلفن نیست.

گزارش سراسری CDR عمداً به مدیر دارای منوی کاربران محدود است. فیلتر داخلی در آن یک محدودیت امنیتی واحد محسوب نمی‌شود. حساب کاربری موجود و APIهای نشست مرورگر را نباید به‌عنوان API اختصاصی سایت معرفی کرد؛ API دارای اعتبارنامهٔ مستقل و محدودهٔ داخلی‌ها و خطوط هنوز پیاده نشده است. از این رو دسترسی به داخلی‌های خارج صف، خط اختصاصی و ضبط‌های مربوط به آن‌ها از راه ایمن واحدی در نسخهٔ فعلی قابل ادعا نیست.

## مدل موردنیاز

۱. هر واحد شناسهٔ مجزا و انتساب‌های تاریخ‌دار و قابل بازنگری برای صف، داخلی، خط ورودی (DID) و ترانک دارد. انتقال مالکیت داخلی یا شماره در آینده نباید به‌طور خودکار اطلاعات تاریخی واحد قبلی را افشا کند. نبود شاهد تاریخی یعنی دسترسی نامعلوم و پیش‌فرض رد.
۲. حساب مدیر واحد و اعتبارنامهٔ سرویس سایت جدا هستند؛ هر یک مجوز مشاهدهٔ گزارش صف، داخلی و شماره، پخش، دانلود و خروجی را مستقل می‌گیرند. لغو یا تغییر مجوز در درخواست بعدی مؤثر است. مجوز شماره به‌صورت جداگانه تعیین و در نبود آن شماره پوشانده می‌شود.
۳. API فقط خواندنی، محدود به بازه و صفحه، بدون دسترسی AMI یا درخواست بلادرنگ از Asterisk است. اعتبارنامهٔ تصادفی باید فقط یک‌بار به مدیر نمایش داده شود، به‌صورت هش نگهداری شود و قابلیت انقضا، لغو، چرخش، نرخ محدود و ثبت دسترسی داشته باشد. اعتبارنامه فقط از سرور سایت در ارتباط HTTPS ارسال شود، نه در کد JavaScript یا نشانی URL.
۴. فیلتر ورودی کاربر حداکثر دامنهٔ مجاز را محدودتر می‌کند و هرگز مجوز ایجاد نمی‌کند. دسترسی به CDR فقط با شاهد قابل اتکای انتساب تاریخی به داخلی یا خط واحد و بررسی هم‌زمان طرف‌ها و مسیر تماس ممکن است؛ جستجوی شماره، شناسهٔ مشترک یا تطبیق رشته به‌تنهایی اثبات مالکیت نیست.
۵. صوت ممکن است شامل IVR، انتقال یا مکالمهٔ واحد دیگری باشد. هنگام هر درخواست پخش/دانلود، مالکیت کل فایل، تمام صف‌ها و واحدهای دخیل و مجوز همان عملیات باید دوباره بررسی شود. ضبط مشترک، ناقص یا انتقال مبهم تا وجود شاهد کافی رد می‌شود. ثبت دسترسی اثبات شنیدن کامل فایل نیست.
۶. پاسخ API نباید مسیر فایل، شناسهٔ خام کانال، توکن، دادهٔ واحد دیگر یا علت ردِ افشاکننده را نشان دهد. خطاها بدون اطلاعات حساس برگردند. لاگ شامل شناسهٔ سرویس، عملیات، زمان، نتیجه و دامنهٔ مجاز است، نه محتوای صوت یا کلید.

## آزمون‌های لازم پیش از ارائه به سایت

آزمون نفوذ واحد A به صف، داخلی، DID، شناسهٔ تماس و فایل صوتی واحد B؛ انتقال A→B و تماس مشترک؛ تغییر عضویت داخلی؛ دادهٔ ناشناخته، نبود یا تأخیر CEL/CDR؛ لغو کاربر، توکن، مجوز شماره یا صوت حین پردازش؛ صفحه‌بندی، حد مجاز درخواست، HTTPS و بار با دادهٔ ساختگی. اعتبارسنجی با یک شماره یا داخلی ثابت، و صرف دریافت HTTP 200، برای تأیید جداسازی کافی نیست.
