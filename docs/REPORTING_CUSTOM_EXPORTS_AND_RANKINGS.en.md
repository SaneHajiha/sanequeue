# Custom exports and agent comparisons

Development update, 2026-10-28. New application changes remain local; an isolated synthetic archive was exercised on the authorised test server. This is not a live-call load certification.

The builder can queue exact CSV/XLSX files or populate a private recurring plan. Columns, filters, groups and queues are frozen independently of subsequent template edits. Snapshot and projection watermark are captured in one short transaction. Pages contain at most 200 visits, readers close between pages, and grouped averages use sufficient statistics over the complete result. Existing row, byte, time, group, cancellation and current-permission boundaries remain enforced. Oversized results fail without publishing partial files. Custom PDF and a separate CDR builder dataset remain pending.

Report navigation separates PBX segments/trunks from contact-center queue metrics, presence and survey work. Segments, queue visits and unique conversations are different units; their totals must not be combined. Recording/journey access still requires authorised queue ownership evidence.

Agent comparison supports known answered-visit counts and average talk for completed answered queue segments. Transferred segments are excluded from this average. Users choose a minimum sample size and a Top limit. Equal values retain equal ranks; a tie crossing the row limit is disclosed. This is not a quality score, and shorter talk is not necessarily better. Local aliases require contemporaneous historical identity evidence before combining queue memberships. Missing evidence, stale projection and resource limits never create a fabricated winner. Table and chart use the same response; charts retain client-side SVG/PNG export.

`tools/generate_reporting_fixture.py` defaults to dry-run. Writing requires a new, isolated destination. On the test server, 870 synthetic events / 150 visits across two queues matched literal expectations for overview, agent groups, builder, CSV and unioned activity. Generation/verification took 0.947 seconds, 0.913 child CPU seconds and 25,200 KiB maximum RSS; Asterisk PID 133041 was unchanged. The production archive was not modified. Synthetic agent rankings also matched expected values: PJSIP/100 had 60 known answers / 37.5-second average; PJSIP/200 had 30 known answers, 15 known durations / 90-second average.

These fixtures do not validate live media, CDR/CEL correlation, external trunks or call capacity. RingGroup/Follow-Me wait attribution, proven abandoned-call follow-up, complete telephone survey intake, automatic historical sources, archive partitioning and full-install recovery remain tracked development gaps. See the Persian companion and `REPORTING_COMPLETION_CHECKLIST.fa.md` for scope and remaining acceptance.
