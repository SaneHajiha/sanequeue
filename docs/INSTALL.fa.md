# نصب خودکار · beta.27 pilot

[English](INSTALL.md) · [راهنمای تصویری](USER_GUIDE.fa.md) · [شواهد آزمون](AUDIT_BETA23.md)

یادداشت زمان‌دار ارزیابی کیفیت، مدت فایل را فقط از فرادادهٔ همان فایلِ مجازشده می‌خواند. برای MP3 و Ogg Vorbis/Opus وابستگی سبک Mutagen را با دستور `/opt/sanequeue/.venv/bin/python -m pip install -r /opt/sanequeue/requirements/reporting.txt` نصب کنید؛ WAV از کتابخانهٔ استاندارد Python استفاده می‌کند. درخواست وب هیچ FFmpeg/FFprobe یا پردازش تبدیل صوت اجرا نمی‌کند. سقف خواندن ۵۱۲ کیبی‌بایت، ۱۰۲۴ عملیات ورودی/خروجی و جابه‌جایی، و مهلت مشارکتی ۲۵۰ میلی‌ثانیه است. نبود تجزیه‌گر، فرادادهٔ خراب یا گذشتن از سقف با HTTP 415 رد می‌شود و یادداشت زمانی ذخیره نمی‌شود؛ پیوست صوتِ مجاز بدون یادداشت، مدت را بررسی نمی‌کند. فراداده به‌تنهایی کامل یا قابل پخش بودن همهٔ صوت را اثبات نمی‌کند.

روی خود سرور PBX، با کاربر root یا sudo اجرا کنید. Linux دارای systemd، Asterisk محلی، AMI فعال روی 127.0.0.1:5038، اینترنت HTTPS و مخزن بستهٔ سالم لازم است. پیش از اجرا متن اسکریپت را بررسی کنید:

```bash
curl -fL https://raw.githubusercontent.com/SaneHajiha/sanequeue/feature/reporting-phase2/scripts/install.sh -o /tmp/sanequeue-install.sh
sudo bash /tmp/sanequeue-install.sh
```

نصب‌کننده کد نسخه را دانلود می‌کند؛ Python مستقل ۳٫۱۰ تا ۳٫۱۲ را استفاده می‌کند یا با ابزار رسمی Astral uv نسخهٔ ۳٫۱۱ می‌گیرد. Python خود ایزابل عوض نمی‌شود. Redis در صورت نیاز از مخزن سیستم نصب می‌شود. روی سیستم‌های قدیمی با مخزن منقضی، ابتدا مخزن باید اصلاح شود؛ سازگاری عملی همهٔ ایزابل‌های ۴/۵ تأیید نشده است.

در نصب نخست نام مدیر، رمز ۱۲ تا ۲۰۰ نویسه (دو بار و بدون نمایش)، داخلی اختیاری سرپرست و آدرس دقیق پنل پرسیده می‌شوند. رمز اولیهٔ مشترک وجود ندارد. در ارتقا حساب‌ها و رمزهای فعلی حفظ می‌شوند. رمز را در خط فرمان یا Issue گیت‌هاب قرار ندهید.

## کارهای خودکار

1. ساخت محیط مستقل زیر `/opt/sanequeue-releases` و پیوند `/opt/sanequeue`.
2. کاربر سیستم محدود `sanequeue` و دادهٔ خصوصی `/var/lib/sanequeue`.
3. دو حساب محلی محدود AMI برای Collector و کنترل تماس، با حفظ حساب‌های دیگر و مالکیت فایل. فقط `manager reload` اجرا می‌شود؛ Asterisk ری‌استارت نمی‌شود.
4. Redis خصوصی با رمز روی 127.0.0.1:16379 و سقف ۱۲۸ مگابایت؛ Redis موجود دست‌نخورده می‌ماند.
5. سرویس وب، Collector، Redis و تایمر خواندن فهرست داخلی‌ها هر ۳۰ ثانیه. وب به رمزهای SIP یا اجرای CLI دسترسی ندارد.
6. کشف خودکار صف‌ها از AMI و داخلی‌های استاندارد ایزابل از تعریف‌های `context=from-internal`. نام عددی ترانک، داخلی محسوب نمی‌شود. برای Dialplan سفارشی، مدیر محلی در `/etc/sanequeue/inventory.ini`، بخش `[inventory]`، مقدار `internal_contexts=from-internal,internal-sales` را تنظیم می‌کند؛ حداکثر ۳۲ نام دقیق و بدون wildcard. Context ترانک را وارد نکنید. نصب مجدد مقدار موجود را حفظ می‌کند. با `systemctl start sanequeue-inventory.service` فهرست تازه می‌شود و تماس‌ها دست‌نخورده می‌مانند. Context انتقال تماس نیز باید با Dialplan همان محل هماهنگ باشد.

آدرس HTTP خصوصی روی همان IP/پورت فعال می‌شود. برای دامنهٔ HTTPS، وب روی loopback پورت ۵۰۰۰ می‌ماند و گواهی، پراکسی و فایروال باید توسط مدیر تنظیم شوند. نصب‌کننده پورت عمومی باز نمی‌کند. AMI و Redis را اینترنتی نکنید.

## کار با پنل

در حالت نصب مدیریت‌شده، صف را دستی فعال نمی‌کنید و دروازهٔ موقت ۳۰ دقیقه‌ای لازم نیست. نقش، منوی مجاز، صف/عمل مجاز، CSRF و تازگی داده سمت سرور بررسی می‌شوند. مدیر همهٔ صف‌ها را می‌بیند؛ نقش‌های دیگر مجوز صریح لازم دارند. در «قوانین صف» حداقل آمادگی، دلایل توقف و آستانهٔ تعداد/زمان را تنظیم کنید. در «تنظیمات» توکن و مقصد تلگرام/بله را وارد و دکمهٔ تست را بزنید؛ توکن ذخیره‌شده دوباره نمایش داده نمی‌شود.

از تصویر بالای پنل نام، داخلی، عکس و رمز خود را تغییر دهید. تغییر رمز یا داخلی نیازمند رمز فعلی است و نشست‌های قبلی را می‌بندد. هر داخلی فقط به یک حساب اختصاص دارد. کنترل‌های تلفنی همچنان بتا هستند؛ مسیر انتقال، پارک و جهت صدای شنود/نجوا باید روی هر پروژه تست شوند.

## بررسی، ارتقا و بازگشت

```bash
systemctl is-active sanequeue sanequeue-collector sanequeue-redis
systemctl list-timers sanequeue-inventory.timer
journalctl -u sanequeue -u sanequeue-collector --since '10 minutes ago'
```

ورود، تعداد اعضا/منتظرها، فهرست داخلی، محدودیت کاربر و یک تماس واقعی را با PBX تطبیق دهید. پذیرش ۲۰۲ فرمان، تأیید اجرای آن نیست. برای ارتقا همان اسکریپت نسخهٔ جدید را اجرا کنید. قبل از تغییر، پشتیبان خصوصی زیر `/var/backups/sanequeue/<timestamp>-installer` ساخته می‌شود و در شکست نصب، کد/تنظیمات/سرویس قبلی برمی‌گردد.

بازگشت دستی: وب، Collector و تایمر را متوقف کنید؛ تنظیمات، داده و unitهای متناظر را از پشتیبان برگردانید؛ پیوند برنامه را به `previous_source` در `result.json` برگردانید؛ فایل‌های AMI را با مالکیت قبلی بازیابی کنید؛ `manager reload` و `systemctl daemon-reload` و سپس سرویس‌های قبلی را اجرا کنید. بازگرداندن دادهٔ قدیمی تغییرات بعد از پشتیبان را از بین می‌برد؛ ابتدا بررسی کنید. برای این کار Asterisk را ری‌استارت نکنید.

پشتیبان حساب‌ها، کلید نشست، رمزهای AMI/Redis، توکن ربات و مقصد پیام‌رسان خصوصی‌اند؛ در گیت‌هاب یا ZIP انتشار نباشند. جزئیات مسیرهای پیشرفته و محدودیت‌ها در [نسخهٔ انگلیسی](INSTALL.md) آمده است.

## توقف اضطراری، حذف و هویت سازمان

در تنظیمات، غیرفعال‌کردن مانیتورینگ اتصال AMIِ Collector، ارسال هشدار و کنترل تماس ماژول را متوقف می‌کند؛ صفحهٔ مدیریت برای فعال‌سازی دوباره باز می‌ماند. خواندن داده فوراً نامعتبر می‌شود و تایمر فهرست داخلی در حالت غیرفعال اجرا نمی‌شود. تماس‌ها، ضبط و مسیر اصلی PBX مستقل ادامه دارند. فرمانی که پیش از غیرفعال‌کردن در PBX پذیرفته شده ممکن است همچنان اجرا شود؛ این کلید آن فرمان را برنمی‌گرداند.

اگر خود پنل باز نمی‌شود، `sudo sanequeuectl disable` فقط سرویس‌های وب، Collector، فهرست داخلی و Redis خصوصی ماژول را متوقف و غیرفعال می‌کند. بازگشت: `sudo sanequeuectl enable`. مشاهدهٔ وضعیت: `sudo sanequeuectl status`.

حذف سرویس‌ها: `sudo sanequeuectl uninstall --yes`. فقط unitهای ماژول و بلوک AMI مدیریت‌شدهٔ آن حذف می‌شوند؛ منبع، داده و تنظیمات خصوصی و پشتیبان حذف، برای بازیابی حفظ می‌شوند. برای بازگرداندن سرویس‌های حذف‌شده نصب‌کننده را دوباره اجرا کنید. این فرمان پاک‌سازی مخرب داده نیست. هیچ‌یک از این عملیات Asterisk را ری‌استارت یا کانال تماس PBX را قطع نمی‌کند.

در «هویت سازمان» نام، عنوان و لوگوی همان پروژه را ذخیره کنید؛ پنل و صفحهٔ ورود به‌روز می‌شوند. تصویر به PNG امن تبدیل می‌شود؛ SVG/HTML یا لینک تصویر خارجی پذیرفته نمی‌شود. اعلان‌های حقوقی ضروری در LICENSE/NOTICE محفوظ‌اند.
