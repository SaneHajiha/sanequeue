# تجمیع پس‌زمینهٔ کارشناسان؛ ابزار خصوصی مدیر فنی

این ابزار جدید، رتبه‌بندی دوشاخصی و اجتماع زمان حضور چندصفی را از یک **پشتیبان
بسته و بررسی‌شدهٔ آرشیو** محاسبه می‌کند. سقف تعاملی پنل عوض نشده است. توکن
snapshot خروجی فعلی فقط مراجعه‌ها را ثابت می‌کند و وضعیت/هویت کارشناس را ثابت
نمی‌کند؛ بنابراین برای این محاسبه از آن به‌تنهایی استفاده نمی‌شود.

## اجرا

هر دو مقصد باید تازه و در مسیر خصوصی مدیر سیستم باشند. دستورها به PBX، AMI یا
SQL مرکز تلفن وصل نمی‌شوند و دیتابیس فعال را تعویض نمی‌کنند. در محیط زیر بار،
فرایند را با سرویس محدود CPU/حافظه و اولویت IO پایین اجرا کنید؛ خود CLI جای
کنترل cgroup را نمی‌گیرد.

```bash
python -m sanequeue.reporting.backup backup /PRIVATE/history.sqlite3 /PRIVATE/NEW_BACKUP
python -m sanequeue.reporting.agent_background \
  --bundle /PRIVATE/NEW_BACKUP --destination /PRIVATE/NEW_RESULT \
  --queue 8001 --queue 8002 --start START_EPOCH --end END_EPOCH --seconds 120
```

آغاز شامل بازه و پایان خارج بازه است؛ epoch همان قرارداد گزارش است. خروجی
`result.json` فقط بعد از بررسی دوبارهٔ checksum پشتیبان و انتشار اتمیک ایجاد
می‌شود. `work.sqlite3` دادهٔ کاری خصوصی است و برای بررسی خطا حفظ می‌شود؛ مقصد
نیمه‌تمام دوباره استفاده نمی‌شود. پاک‌سازی یا حذف دادهٔ خودکار وجود ندارد.

## قرارداد و محدودیت‌ها

- صفحه‌های منبع حداکثر ۲۰۰ ردیف، reader حداکثر ۵ ثانیه؛ زمان کل پیش‌فرض ۱۲۰ و
  حداکثر ۳۰۰ ثانیه؛ سقف ۲۵۰هزار ردیف پیموده‌شده و ۲۰۰۰ هویت است. ردیف‌های
  وضعیت خارج scope نیز هنگام پیمایش محدود منبع، در سقف خواندن حساب می‌شوند.
- دیتابیس کاری حداکثر ۶۴MiB و نتیجه حداکثر ۲MiB است؛ فضای آزاد ۶۴MiB حین
  کار بررسی می‌شود. حافظهٔ مرتب‌سازی SQLite و فرایند به کنترل سرویس نیاز دارد.
- منبع باید projection نسخهٔ جاری و watermark کامل داشته باشد. WAL یا checksum
  ناسازگار، هویت مبهم، اتمام بودجه و شکست دیسک نتیجهٔ موفق منتشر نمی‌کنند.
- رتبه‌بندی از کل ردیف‌های خام مجاز، تعداد نمونه و مجموع مدت معلوم محاسبه
  می‌شود؛ top/minimum-samples بعد از تجمیع است. میانگین میانگین‌های روزانه نیست.
- هویت Local فقط با شاهد هم‌زمان همان صف به endpoint نسبت داده می‌شود. inventory
  امروز هویت تاریخی را تغییر نمی‌دهد. رقابت دو هویت باعث رد نتیجه می‌شود.
- شاهدهای پیوستهٔ هویت با کلید صف/alias/endpoint مستقل از تغییر وضعیت آماده،
  مکالمه یا توقف در جدول کاری به span تبدیل می‌شوند. شکاف زمانی و دو endpoint
  متفاوت حفظ می‌شوند. جست‌وجوی هر تماس روی شاخص span انجام می‌شود؛ تاریخچهٔ
  تمام تغییر وضعیت‌ها برای هر تماس دوباره اسکن نمی‌شود.
- حضور، مکالمه، توقف و ACW صریح با اجتماع بازه‌های همان endpoint در صف‌های
  منتخب محاسبه می‌شوند. جمع زمان عضویت دو صف، زمان یکتای کارشناس نیست.
- نبود ACW مقدار `null` می‌دهد. نبود پوشش یا حالت ناشناخته، پوشش کامل اعلام
  نمی‌شود. دادهٔ غایب با صفر یا غیبت پر نمی‌شود. رتبه‌بندی امتیاز کیفیت نیست.

## چه چیزی هنوز کامل نشده است؟

این یک CLI خصوصی مدیر سیستم است، نه endpoint وب یا job عمومی. مجوز جاری کاربر
در آن خوانده نمی‌شود و فایل نتیجه مجوز تازه‌ای ایجاد نمی‌کند؛ مدیر فنی مسئول
انتخاب scope و نگهداری خصوصی نتیجه است. برای عرضه در پنل، ایجاد/مشاهده/دانلود
job باید مجوز جاری را دوباره بررسی کند و snapshot ثابت وضعیت/هویت نیز برقرار
باشد. افزایش سقف HTTP یا استفادهٔ مستقیم از این تابع در request مجاز نیست.

شاخص‌های کامل AHT/occupancy، اثبات مرز ACW با پایان صف، carry-in تماس، تاریخچهٔ
جامع منابع و تمام شرایط تماس پیچیده در این خروجی عرضه نشده‌اند. پذیرش ماهانهٔ
این ابزار باید جداگانه ثبت شود؛ نتیجهٔ قبلی fixture ماهانه مربوط به این موتور
جدید نیست. تکمیل CLI به معنی پایان تمام توسعهٔ حضور/رتبه‌بندی پنل نیست.
