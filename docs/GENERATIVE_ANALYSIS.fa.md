# تحلیل مولد اختیاری متن مکالمه

این قابلیت، **متن تکمیل‌شدهٔ تبدیل گفتار** را به یک سرویس مدلِ از قبل آماده روی loopback می‌دهد؛ خودِ پنل مدل اجرا/دانلود نمی‌کند و صوت به این سرویس نمی‌فرستد. خروجی شامل خلاصه، موضوع‌ها و ایده‌های پیگیری با ارجاع به قطعهٔ متن و ثانیهٔ فایل اصلی است. نتیجه همیشه «ماشینی و نیازمند بازبینی» است؛ تصمیم خودکار دربارهٔ کارکنان، امتیاز استخدامی یا اجرای پیشنهادها وجود ندارد. داشتن ارجاع، درستی برداشت مدل را اثبات نمی‌کند.

## استفاده در پنل

۱. در جزئیات مراجعه، ضبطِ مجاز را باز و تبدیل گفتار را تکمیل کنید.
۲. کنار دکمهٔ نمایش متنِ کار تکمیل‌شده، «تحلیل مولد اختیاری» را انتخاب کنید.
۳. زبان فارسی یا انگلیسی و تأیید بازبینی انسانی را انتخاب، سپس درخواست تحلیل را ثبت کنید.
۴. با «بازخوانی وضعیت» نتیجه را ببینید؛ polling خودکار وجود ندارد. در نتیجه، پیوند `s1` و مشابه آن به متن و زمان واقعی همان منبع ثابت می‌رود، نه URL یا صوتی که مدل پیشنهاد کرده باشد.
۵. صف/صوت باید در لحظهٔ درخواست، پردازش و خواندن نتیجه همچنان مجاز باشند. کاربر فقط کارهای خودش را می‌بیند. حذف دسترسی، تغییر متن منبع یا ناتوانی در اثبات مالکیت ضبط، نمایش/انتشار نتیجه را می‌بندد.

## فعال‌سازی توسط مدیر

پیش‌فرض خاموش است. این پیاده‌سازی هیچ سرویس مدل یا وزنی نصب نمی‌کند. ابتدا یک سرویس محلی سازگار با `/v1/chat/completions` را **جدا از پردازش تماس و وب** آماده و مصرف CPU/RAM آن را مستقل محدود کنید. برای نمونهٔ قرارداد API به [راهنمای رسمی سرور llama.cpp](https://github.com/ggml-org/llama.cpp/tree/master/tools/server) مراجعه کنید؛ نام مدل، وزن، کیفیت فارسی و کارایی مدل انتخاب‌شده در این تغییر آزموده نشده‌اند.

فایل `/etc/sanequeue/generative.json` خصوصی با مجوز `0600` و قابل‌خواندن برای کاربر `sanequeue` بسازید:

```json
{
  "enabled": true,
  "allow_local_transcript_processing": true,
  "endpoint": "http://127.0.0.1:8080/v1/chat/completions",
  "model": "local-model-id",
  "timeout_seconds": 30,
  "max_tokens": 1024,
  "json_mode": false
}
```

`model` باید نام واقعی مدلِ سرویس آمادهٔ شما باشد. `api_key` اختیاری فقط در همین فایل خصوصی پذیرفته می‌شود؛ در چت، فرم وب، job یا لاگ نوشته نمی‌شود. اگر سرویس `response_format: json_object` را پشتیبانی می‌کند، `json_mode` را فعال کنید؛ در هر دو حالت پاسخ باید JSON کامل طبق قرارداد باشد.

وب فقط با `SANEQUEUE_TEXT_ANALYSIS_ENABLED=1` اجازهٔ درخواست جدید می‌دهد. worker با فایل opt-in `/etc/sanequeue/generative.enabled` و واحد [sanequeue-generative.service](../deploy/sanequeue-generative.service) قابل اجراست. مسیرهای واحد را با محل نصب خودتان تطبیق دهید؛ فایل‌های حساب و سیاست جاری باید در دسترس worker باشند. پایگاه `generative-jobs.sqlite3` باید **جدا** از `ai-jobs.sqlite3` و آرشیو باشد. حالت یک‌بار اجرا برای آزمون مصنوعی/تحت نظارت:

```sh
python -m sanequeue.reporting.generative_worker \
  --jobs /var/lib/sanequeue/generative-jobs.sqlite3 \
  --sources /var/lib/sanequeue/ai-jobs.sqlite3 \
  --archive /var/lib/sanequeue/history.sqlite3 \
  --config /etc/sanequeue/generative.json \
  --scratch /var/lib/sanequeue/generative-scratch \
  --accounts /var/lib/sanequeue/local_accounts.json \
  --policies /var/lib/sanequeue/local_queue_policies.json --once
```

برای قطع تأیید پردازش در حین کار، `enabled` تنظیمات را false یا کل ماژول را با مکانیزم `module.disabled` غیرفعال کنید. لغو پنل از انتشار نتیجه جلوگیری می‌کند و فرایند درخواست را متوقف می‌کند؛ لزوماً محاسبهٔ سرویس مدلِ جدا را متوقف نمی‌کند. حذف فایل Condition پس از شروع سرویس، خودبه‌خود آن فرایند را متوقف نمی‌کند.

## مرزهای امنیت، منابع و صحت

- فقط `http://127.0.0.1:PORT/v1/chat/completions` یا `http://[::1]:PORT/v1/chat/completions`، پورت ۱۰۲۴ تا ۶۵۵۳۵، بدون query، fragment، نام کاربری و redirect. نام میزبان/DNS، URL ابری و proxy محیط پذیرفته نیست. مدیر باید مطمئن شود سرویس loopback خودش proxy سرویس ابری نیست؛ این کد زیرساخت آن سرویس را تأیید نمی‌کند.
- متن/segments و spec کار ASR با SHA-256 ثابت می‌شوند. متن باید حداکثر ۱۶هزار کاراکتر و ۴۸KiB، حداکثر ۲۰۰ قطعه و کامل با متن قطعه‌ها منطبق باشد؛ ورودی بزرگ بریده نمی‌شود. درخواست HTTP حداکثر ۶۴KiB، پاسخ ۶۴KiB و نتیجهٔ خصوصی ۱۲۸KiB است.
- timeout سوکت مدل حداکثر ۳۰ ثانیه؛ سقف wall-clock واقعی را worker با ۴۵ ثانیه و child قابل‌کشتن اعمال می‌کند. helper شبکه نباید مستقل و بدون ناظر اجرا شود؛ سوکت به‌تنهایی پاسخ آهسته/قطره‌ای را به سقف قطعی تبدیل نمی‌کند. یک worker هم‌زمان؛ صف حداکثر ۳ کار فعال برای هر مالک و ۱۰ کار فعال در کل، حداکثر ۳ تلاش برای بازیابی lease. کمبود منابع کار را بدون مصرف تلاش به تعویق می‌اندازد.
- کارگر مجوز فعلی نقش/منو و تمام صف‌های ثابت و انتساب ضبط را قبل، حین و پس از اجرا بررسی می‌کند. پایگاه خصوصی فقط متن‌های ارجاع‌شده و خروجی را نگه می‌دارد؛ هیچ حذف خودکار متن/صوت/گزارش اعمال نمی‌شود. فایل‌های موقت متعلق به همین پردازش پس از پایان پاک می‌شوند.
- `CPUQuota=10%` و `MemoryMax=192M` فقط worker و child شبکه‌ای را محدود می‌کنند؛ **مصرف مدل جداگانه را محدود نمی‌کنند**. بار و دقت واقعی مدل، فارسی واقعی و اثر بر تماس‌ها هنوز آزمون پذیرش جدا می‌خواهند. از تست HTTP مصنوعی، نتیجهٔ «مناسب سرور زیر بار» گرفته نمی‌شود.

## اتصال توسعه‌دهنده

`sanequeue.api.generative.install(app, ai_store, archive, role=role, sections=sections, can_queue=can_queue, authorize_source=callback)` را یک بار در نصب API فراخوانی کنید. callback با `(source_spec, deadline=None)` باید احراز فعلی صوت/مراجعه را با هویت دقیق انجام دهد و صف‌های اثبات‌شدهٔ ضبط را برگرداند؛ callback نباید صرفاً true برگرداند. در API موجود، `ai_authorized(..., by_identity=True, deadline=deadline)` مناسب است. سپس `generative-reports.js` را با `theme_static` و `defer` پس از `ai-reports.js` بارگذاری کنید. هیچ تغییری در پیاده‌سازی ASR لازم نیست.
