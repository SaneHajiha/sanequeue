# API گزارش واحد — شاخهٔ توسعه

این رابط فقط آرشیو SaneQueue را می‌خواند و نیاز به نام کاربری یا دسترسی AMI ندارد. هنوز نصب عملیاتی و آزمون سرتاسری روی سرور انجام نشده است. فقط HTTPS پذیرفته می‌شود؛ در نصب پشت reverse proxy باید تشخیص HTTPS در برنامه با پیکربندی معتبر و قابل‌اعتماد انجام شود.

ابتدا برای حساب موردنظر مجوزهای «API» و «خلاصه گزارش» یا «ریز تماس» در محدودهٔ واحد لازم را ثبت کنید. مجوز API به‌تنهایی داده‌ای نمی‌دهد. محدودهٔ API باید همهٔ واحدهای محدودهٔ گزارش مربوط را پوشش دهد؛ در غیر این صورت درخواست رد می‌شود. شمارهٔ کامل علاوه بر مجوز مستقل به نقش مجاز مدیر یا سرپرست نیاز دارد. صدور توکن باید توسط صاحب همان حساب پس از ورود و در صفحهٔ گزارش واحد روی HTTPS انجام شود. کلید فقط یک‌بار نمایش داده می‌شود، ۱ تا ۹۰ روز اعتبار دارد و باید خارج از کد و مخزن نگهداری شود.

درخواست‌ها با هدر `Authorization: Bearer <TOKEN>` ارسال می‌شوند؛ کلید را در URL قرار ندهید. دو مسیر خواندنی موجودند:

- `GET /api/organization/integration/summary?from=2026-10-24&to=2026-10-25`
- `GET /api/organization/integration/cdr?from=2026-10-24&to=2026-10-25&limit=50`
- `GET /api/organization/integration/trend?from=2026-10-24&to=2026-10-25&bucket=day`
- `GET /api/organization/integration/export.csv?from=2026-10-24&to=2026-10-25`؛ قالب‌های `export.xlsx` و `export.pdf` نیز موجودند.
- `GET /api/organization/integration/recording/<ref>` برای پخش؛ برای دانلود `?download=1` اضافه کنید. `ref` ارجاع موقتی است که در ردیف مجاز CDR بازگردانده می‌شود، نه نام فایل یا شناسهٔ اصلی تماس.

تاریخ ورودی ISO و پایان شامل روز انتخاب‌شده است؛ بازه حداکثر ۳۶۶ روز است. پاسخ ریز حداکثر ۱۰۰ ردیف و در صورت وجود صفحهٔ بعد، `next` دارد. برای صفحهٔ بعد همان تاریخ و فیلتر و اندازهٔ صفحه را همراه `cursor=<next>` بفرستید. توکن صفحه به همان کاربر، گزارش و نسخهٔ مجوز مقید است و پس از تغییر مجوز معتبر نیست. جهت، نتیجه و فیلترهای مدت و ساعت مجازند. جست‌وجوی `src`، `dst`، `party`، `origin` و `endpoint` فقط برای نقش مدیر یا سرپرست دارای مجوز شمارهٔ کامل در **تمام واحدهای محدودهٔ گزارش** مجاز است. `endpoint` حداکثر ۲۰ شناسهٔ دارای فناوری و جداشده با ویرگول را می‌پذیرد. جست‌وجو فقط روی ردیف‌های مجاز و دارای شاهد انتساب اعمال می‌شود.

نمونهٔ درخواست با ابزار کلاینت از محیطی که متغیر `SANEQUEUE_TOKEN` را امن دریافت کرده است:

```sh
curl --fail --header "Authorization: Bearer $SANEQUEUE_TOKEN" \
  'https://YOUR-SANEQUEUE/api/organization/integration/summary?from=2026-10-24&to=2026-10-25'
```

توکن را می‌توان در همان صفحه ابطال کرد؛ حذف حساب محلی از مسیر پنل نیز توکن‌های آن را باطل می‌کند. اعتبار حساب، مجوز و نقش پیش و پس از تولید نتیجه بررسی می‌شوند. خروجی به مجوز مستقل ریز تماس و خروجی و نقش مدیر یا سرپرست نیاز دارد؛ سقف CSV و Excel پنج‌هزار ردیف و PDF صد و پنجاه ردیف است. روند به مجوز خلاصه نیاز دارد. سقف هر توکن ۱۲۰ درخواست و سقف مشترک هر PBX پنج‌هزار درخواست در دقیقه است. ردیف‌ها بخش CDR هستند، نه لزوماً مکالمهٔ یکتا، و رکورد فاقد شواهد داخلی ممکن است نمایش داده نشود. صوت فقط برای تماس مستقیم تک‌بخشی که مالکیت کل فایل آن اثبات شود و با مجوزهای مستقل ریز تماس، API و پخش یا دانلود قابل استفاده است؛ ارجاع ۱۵ دقیقه اعتبار دارد و تغییر مجوز آن را باطل می‌کند. تماس صف، انتقال و فایل مشترک در این مسیر بسته‌اند. گزارش صف در این API هنوز پشتیبانی نمی‌شود. انطباق عمر هویت در محیط چندفرایندی یا هنگام تغییر مستقیم فایل حساب بیرون از پنل هنوز تضمین نشده است.

پس از تأیید توکن، زمان، حساب، شناسهٔ غیرمحرمانهٔ توکن، نوع گزارش و نتیجهٔ HTTP در حسابرسی محلی ثبت می‌شود؛ کلید، فیلتر، شماره و محتوای پاسخ ثبت نمی‌شوند. ثبت‌های حسابرسی در `GET /api/organization/access/audit` برای مدیر سراسری مجاز قابل مشاهده‌اند. اگر ثبت ممکن نباشد، پاسخ داده تحویل نمی‌شود. این جدول سقف ۱۰۰ هزار رکورد برای هر PBX دارد و پاک‌سازی خودکار ندارد؛ مدیریت ظرفیت و نگهداری آن باید پیش از بهره‌برداری تعیین شود. تلاش‌های بدون توکن معتبر در این جدول ثبت نمی‌شوند.
