## Archive backup development continuation

The operator-only `python -m sanequeue.reporting.backup` CLI adds online backup,
verification and restore into a new private directory. It uses standard-library
SQLite with short backup steps/yields and time/size/free-space ceilings. It
includes committed WAL and checkpoints, never checkpoints/deletes the source,
and never switches a running service or overwrites an existing destination.

The independent reporting reviewer identified a premature completion-marker
publication boundary on manifest fsync failure. The marker now uses an exclusive
private temporary file, fsync and non-overwriting hardlink publication. A failed
post-publication directory sync retires only that owned marker when storage
permits; the database remains. If storage also refuses unlink, durability is
indeterminate: any failed operation requires operator investigation, not automatic
acceptance of an existing file. The API has no web route.

Thirteen local tests passed, including a true os._exit before completion, committed
WAL snapshot/checkpoints, corruption, no-overwrite restore, disk/size/deadline and
actual manifest fsync/after-publication sync fault injection. One Unix symlink test
is skipped on Windows and runs on Linux CI. Windows fsync required reopening the
private destination with write access; this portability defect was fixed.

This is an archive-only drill, not full-installation disaster recovery, partition
routing, live cutover or power-loss certification. Guides: ARCHIVE_BACKUP.fa.md
and ARCHIVE_BACKUP.en.md. No PBX process, live archive or private server data was
changed for this development.
